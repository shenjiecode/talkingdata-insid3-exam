# 设计说明：种子评分不能直接复用为聚合评分

| 项目 | 说明 |
| --- | --- |
| 选择的考点 | 论文 §3.3–3.4 的种子选择和区域聚合。作者固定版本 `_seed_and_aggregate` 的 L336–339 用归一化 cluster 原型选择种子；L349–354 则对 cluster 内的逐 patch 跨图相似度求均值；L330–334、L356–363 加入覆盖比例并判断阈值。两处评分看起来相近，实际保留的信息不同。 |
| 题目思路 | 输入已准备好的原始特征、去偏特征、聚类标签和候选 patch 掩码，要求补一个 NumPy 函数。把特征提取、SVD 和聚类都排除后，错误可以定位到这段评分与聚合逻辑。 |
| 难点假设 | GPT-5.5 可能把“区域相似度”统一写成归一化均值原型的余弦相似度，并在聚合阶段复用种子评分。这种写法简洁，也贴近论文式 (9)–(13) 的直观理解，却忽略了当前作者代码在聚合阶段使用逐 patch 分数均值的细节。这里只提出假设，没有实际调用 GPT-5.5。 |
| 最小验证例子 | 测试主例有 8 个 patch、3 个 cluster。参考原型是 `(0,1,0)`。cluster 1 的四个去偏 patch 为两个 `(0,0.6,0.8)` 和两个 `(0,0.6,-0.8)`。它们均值的方向恰好指向参考，但逐 patch 分数均值只有 `0.6`。候选掩码只覆盖其中 1/4，图内相似度为 `1`，所以聚合分数是 `0.15`。阈值为 `0.2` 时不应选中。 |
| 预期错误结果 | 若把均值原型重新归一化后算跨图分数，cluster 1 的分数会从 `0.6` 变成 `1`，最终得到 `0.25`，错误地越过阈值。若遗漏覆盖比例，会得到 `0.6`，也会误选。 |
| 如何判断 | `test_bonus_task.py` 同时断言中间分数与完整掩码：cluster 1 的 `cross_similarity=0.6`、`area_weights=0.25`、`combined_scores=0.15`，四个 patch 全部不入选。其他小例检查特征空间、候选集合、种子权重、阈值及空候选分支，避免只靠一个最终掩码碰巧通过。 |

## 为什么这个错误值得测

设一个 cluster 的去偏单位特征均值为 `m`，参考单位原型为 `p`。逐 patch 相似度均值等于 `m·p`；把 `m` 归一化后再算，则是 `(m/||m||)·p`。后者去掉了均值的长度，也就丢掉了 patch 方向是否一致的信息。

主例中，正负第三通道在平均时抵消，归一化均值看上去和参考完全相同。但四个 patch 单独与参考比较，得分都只有 `0.6`。这样的“区域方向正确、内部特征分散”输入，比只有单 patch 或完全一致 patch 的例子更能区分两种实现。

## 主例的完整预期

按行优先顺序，标签为 `[0,0,1,1,1,1,2,2]`，网格为 `2×4`。

| cluster | 原始 patch | 去偏 patch | 候选覆盖 | 跨图分数 | 图内分数 | 最终权重 | 聚合分数 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 两个 `(0,1,0)` | 同原始 | 1/2 | 1 | 1 | 1（种子） | 1 |
| 1 | 两组 `(0,0.6,±0.8)` | 同原始 | 1/4 | 0.6 | 1 | 0.25 | 0.15 |
| 2 | 两个 `(√3/2,0.5,0)` | 两个 `(0,1,0)` | 1/2 | 1 | 0.5 | 0.5 | 0.25 |

两套特征与去除第一通道的位置子空间一致。三个 cluster 的去偏均值原型都指向参考，按题面明确的同分规则选标签 0 为种子。阈值 `0.2` 时，最终标签为 0 和 2；cluster 2 中未被候选掩码标记的 patch 也随整个 cluster 入选。

额外断言分别用于识别：

- 使用去偏特征计算图内相似度：cluster 2 的图内分数会从 `0.5` 变成 `1`。
- 没有把种子的覆盖权重设为 1：cluster 0 的权重会停留在 `0.5`。
- 在所有 cluster 中选择种子：第二个例子中不属于候选集合的 cluster 0 得分最高，但正确种子应为 cluster 1。
- 把作者的 `>` 改成 `>=`，或无条件保留种子：阈值边界例子会失败。

最后一项涉及论文与代码的差别：论文式 (14) 写了并入种子和 `≥α`，固定版本代码 L358–363 只修改种子权重，随后对所有 cluster 使用 `> merge_threshold`，并没有单独把种子加回掩码。本题已经明确以该代码版本为准，因此这是需要读代码确认的行为，不是隐藏条件。

## 测试交接

将模型答案放进 `src/insid3_bonus.py`，运行 `python -m pytest -q bonus/test_bonus_task.py`。
本仓库不附模型待写的答案文件；尚未放入答案时，显式运行加分测试会提示缺少文件，不会假装通过。
默认 `python -m pytest -q` 只运行第一题，配置见 `pytest.ini`。

为便于在仓库外检查测试，也支持通过环境变量 `INSID3_BONUS_SOLUTION` 指定待测 `.py` 文件的绝对路径；默认仍使用题面约定的位置。
测试的实际自检结果将在完成运行后记录于 README。
